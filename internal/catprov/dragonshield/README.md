# dragonshield

Dragon Shield catalog provider. It scrapes the card sleeve collection and
returns `catalog.Item` values ready to be persisted with
`catalog.Service.UpsertItems`.

Dragon Shield is protected by Cloudflare, so the provider uses the
[`Chromedp`](../../retrier/README.md#chromedp-transport) retrier instead of plain
HTTP or Colly. A real browser is required to pass the JavaScript challenge.

## Public API

```go
type Provider struct {
    // ...
}

func New() *Provider

func (p *Provider) GetSleeves(ctx context.Context) ([]catalog.Item, error)

var ErrSleevesNotFound = errors.New("sleeves not found")
```

`GetSleeves` returns one `catalog.Item` per product variant. `ErrSleevesNotFound`
is returned when no usable sleeves are collected.

## Flow

```text
GetSleeves
  └── retrier.NewChromedp()
        ├── /collections/card-sleeves
        │     ├── extract product URLs
        │     │     ├── .js-collection-grid a[href]
        │     │     └── fallback: var meta = {"products": [...]}
        │     ├── extract rel=next
        │     └── add product pages
        │
        └── /products/<handle>
              └── parseProductPage
                    └── catalog.NewSleeve(...)
```

The default collection is:

```text
https://www.dragonshield.com/collections/card-sleeves
```

At the time of writing it contains 11 pages with 16 products per page and
produces about 230 sleeve items because some products have multiple variants.

## Collection pages

The visual product grid is rendered by JavaScript. The initial DOM contains
skeleton cards:

```html
<div class="tvg_grid_EuV06q_skeletonCard">...</div>
```

The provider therefore tries two sources for product URLs:

1. `.js-collection-grid a[href]`, when the grid has already hydrated.
2. The embedded Shopify object:

```html
<script>
  var meta = {
    "products": [
      {"handle": "black-matte-sleeves", ...}
    ]
  };
</script>
```

The fallback builds `/products/<handle>` URLs and is the normal path while the
grid is showing skeletons.

Pagination is read from `a[rel="next"]` / `link[rel="next"]`.

## Product mapping

| Catalog field | Source |
| --- | --- |
| `Kind` | `catalog.KindSleeve` |
| `Brand` | `catalog.BrandDS` |
| `Lang` | `catalog.LangEN` |
| `Code` | Variant SKU; fallback to visible SKU. |
| `Name` | Variant name; fallback to `h1`. |
| `Description` | Empty |
| `Image.URLSmall` | Main gallery image with `width=480` |
| `Image.URLLarge` | Main gallery image with `width=800` |
| `ReleaseAt` | Zero value |
| `ItemInfoID` | `nil` |

### Variants

Variants are read from:

```html
<script type="application/json" class="js-product-options-props">
  {"product": {"variants": [{"id": ..., "name": ..., "sku": ...}]}}
</script>
```

Each variant becomes a separate item. For example:

```text
Black - Matte Sleeves - Standard   AT-11002
Black - Matte Sleeves - Japanese   AT-11102
```

If the JSON is missing, the provider creates one item from the visible SKU.

### Subtypes

| Key | Source |
| --- | --- |
| `color` | Current swatch title; fallback original. |
| `size` | Specification `Size`, fallback variant title |
| `texture` | Specification `Texture` |
| `glare_type` | Specification `Glare Type` |
| `quality` | Specification `Quality` |
| `items_per_case` | Specification `Items per case` |
| `material` | Specification `Material` |
| `layer` | Specification `Layer` |
| `clear` | `true` when the item name contains `clear` |

Specifications come from:

```html
<div class="..._ProductSpecifications__list">
  <div class="..._ProductSpecifications_item">
    <h3 class="..._ProductSpecifications_item-title">Size</h3>
    <div class="..._ProductSpecifications_item-description" data-variant-id="...">Standard</div>
  </div>
</div>
```

Specification values with `data-variant-id` are resolved per variant. Shared
values apply to every variant. Titles are normalized to snake_case.

### Images

The main image is taken from:

```css
.js-product-gallery-image img
```

The source is normalized to `https://` and both sizes are generated by setting
the `width` query parameter:

```text
https://www.dragonshield.com/cdn/shop/files/example.png?v=...&width=480
https://www.dragonshield.com/cdn/shop/files/example.png?v=...&width=800
```

## Usage

The command in `cmd/sync/dragonshield` scrapes and upserts the result:

```powershell
go run ./cmd/sync/dragonshield
```

It reads `DB_URL` from the environment or from `.env`. The browser is detected
automatically. To force a specific browser:

```powershell
$env:DRAGONSHIELD_BROWSER="C:\path\to\brave.exe"
go run ./cmd/sync/dragonshield
```

The browser window is visible by default because Cloudflare may challenge a
headless browser. If a challenge appears, it can be solved in the window.

## Tests

Unit tests use HTML fixtures and do not open a browser:

```powershell
go test ./internal/catprov/dragonshield
```

Live tests are opt-in because they open a browser and can take several minutes:

```powershell
$env:DRAGONSHIELD_LIVE="1"

go test ./internal/catprov/dragonshield `
  -run TestGetSleevesLive -v `
  -count=1 -timeout 12m
```

`TestGetSleevesLive` scrapes the real collection and fails when no items are
returned. A successful run at the time of writing collected 230 sleeves in about
5m24s.

The retrier navigation test lives in
[`internal/retrier/chromedp_test.go`](../../retrier/chromedp_test.go).

## Notes

- The browser profile is temporary and is removed after `Run`.
- Product pages that fail are logged; successful items are still returned.
- The collection URL is currently a constant in `catprov.go`.
- `subtypes` is part of the catalog item identity, so variants that differ only
  by subtype can coexist.
